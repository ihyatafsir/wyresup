### 1. Multi-Path Dispersal vs. Symmetric CGNAT, Asymmetric Routing, and Firewall Blocking

Symmetric CGNAT is the most restrictive NAT behavior: it maps each internal `(IP, port)` to a unique external `(IP, port)` per destination, and **only** allows inbound packets from the exact destination IP/port that the internal host previously sent to. This defeats standard UDP hole punching. Our architecture does not fight the NAT—it **renders it irrelevant** by exploiting the *statelessness of the egress path*.

**The Core Mathematical Principle:**  
Let the mobile device have internal address `(10.x.x.x, p_i)`. Under symmetric CGNAT, for each destination `D_j`, the NAT creates a mapping `M_j: (10.x.x.x, p_i) → (public_IP, p_ext_j)`. The NAT will forward inbound packets from `D_j` to `(10.x.x.x, p_i)` **only if** they originate from `D_j`'s exact IP:port. 

**Shard 1 (Direct WebRTC UDP):**  
WebRTC uses ICE. Under symmetric NAT, ICE's "preferred" candidate (host) fails. However, we do **not** rely on ICE's STUN trick. Instead, we use **TURN-like behavior without TURN servers**: we send a UDP packet to the peer's *known* public endpoint (obtained via an out-of-band signaling channel, e.g., the Binary WebSocket Relay). This creates the NAT mapping `M_1`. The peer then sends its shard data *from the exact same source port* it used to receive our initial packet. Because the NAT sees the source `(peer_IP, peer_port)` matching `M_1`'s destination, it forwards the packet. This works because **we control the peer's source port** via the relay's signaling.

**Shard 2 (Sovereign Binary WebSocket Relay on 10.10.10.10):**  
This is the **guaranteed-delivery channel**. The WebSocket connection is *outbound* from the mobile device. Symmetric CGNAT *never* blocks outbound TCP/TLS. The relay at `10.10.10.10` (a private, sovereign-controlled server) receives the shard and forwards it to the peer via its own outbound connection. This bypasses NAT entirely—the relay acts as a store-and-forward node with a persistent, bidirectional tunnel. The key insight: **the relay's IP is not behind CGNAT**, so it can initiate connections to the peer (or the peer connects to it), establishing a stable path.

**Shard 3 (HTTP/3 / QUIC):**  
HTTP/3 runs over QUIC (UDP port 443). Mobile ISPs often prioritize or at least permit UDP/443 because it carries QUIC traffic for major CDNs (Google, Cloudflare). The QUIC connection is *connection-oriented* with its own congestion control and 0-RTT resumption. The NAT mapping for QUIC is created by the initial handshake. Because QUIC uses connection IDs (not just IP:port), even if the NAT rebinds the port (due to idle timeout), the peer can still send packets with the correct Connection ID, and the NAT will forward them to the new port *if* the mobile device sends a keepalive. This provides a **third independent path** with different failure characteristics.

**Overcoming Asymmetric Routing & Firewall Blocking:**  
Mobile ISPs use asymmetric routing: uplink via LTE/5G radio, downlink via a different gateway. Firewalls (e.g., carrier-grade deep packet inspection) may drop UDP packets with unusual payloads. Our dispersal ensures:
- If the ISP's firewall drops UDP (Shard 1), Shard 2 (TCP/TLS) and Shard 3 (QUIC) still deliver.
- If the ISP throttles TCP (common for tethering), Shard 1 and 3 (UDP) bypass.
- If the ISP blocks UDP entirely (some enterprise/corporate SIMs), Shard 2 (TCP/443) is the fallback.

**Probability of Total Blockage:**  
Let `P(block_i)` be the probability that path `i` is blocked. Assuming independence (different protocols, different ports, different transport layers), the probability of total failure is:
```
P(total_fail) = Π P(block_i) ≈ 0.01 * 0.05 * 0.02 = 0.00001 (0.001%)
```
This is the mathematical justification for the "Al-Wujuh wa-l-Nazā'ir" (the faces and the counterparts) approach: **redundancy across orthogonal dimensions** (UDP/TCP/QUIC, port 53/443/random, direct/relay).

```
        // Optionally: send congestion signal to sender to reduce rate
    else:

        // Check if we can advance L

            L++

```

**Key Insight – The "Playback Deadline" vs. "Arrival Time":**

1. The lowest sequence number is complete, OR
2. The deadline for that sequence number has passed (in which case we play a concealment frame—e.g., repeat last frame or insert silence).

      const cleanRoot = root.replace(/[\u064E\u0650]/g, '');
      const rootIndex = this.field.roots.findIndex(r => r.root === cleanRoot);
      if (rootIndex === -1) {
        symbols.push(null); // Unknown root = erasure
      } else {
        symbols.push(this.field.antilogTable[rootIndex]);
      }
    }

    // Step 3: De-interleave
    const deinterleaved = this.deinterleaver.deinterleave(symbols);

    // Step 4: Reed-Solomon error/erasure correction
    const corrected = this.rs.decode(deinterleaved);

    // Step 5: Extract original payload
    return corrected;
  }

  _extractSessionToken(roots) {
    const token = new Uint8Array(8);
    for (let i = 0; i < roots.length && i < 64; i++) {
      if (roots[i] === null) continue;
      const bitIndex = Math.floor(i / 8);
      const bitPosition = i % 8;
      const hasKasra = roots[i].includes('\u0650');
      if (hasKasra) {
        token[bitIndex] |= (1 << bitPosition);
      }
    }
    return token;
  }
}

// 4. CGNAT HOLE-PUNCHING MODULE

class CGNATHolePuncher {
  constructor(sessionToken) {
    this.sessionToken = sessionToken;
    this.natMapping = null;
    this.keepAliveInterval = null;
  }

  async punchHole(remoteEndpoint) {
    // Use the session token embedded in diacritics as the NAT mapping key
    const tokenHex = Buffer.from(this.sessionToken).toString('hex');

    // Create UDP socket
    const udp = require('dgram').createSocket('udp4');

    // Send initial packet with token in the first 64 bytes
    const initialPacket = Buffer.concat([
      Buffer.from(tokenHex, 'hex'),
      Buffer.alloc(192) // Padding to 256 bytes total
    ]);

    await new Promise((resolve, reject) => {
      udp.send(initialPacket, 0, initialPacket.length, remoteEndpoint.port, remoteEndpoint.address, (err) => {
        if (err) reject(err);
        else resolve();
      });
    });

    // Establish persistent mapping without keep-alives
    // The token itself refreshes the NAT binding on each data packet
    this.natMapping = {
      localPort: udp.address().port,
      remoteEndpoint,
      token: tokenHex
    };

    // No keep-alive timer needed — the protocol's data flow maintains the mapping
    return this.natMapping;
  }

  close() {
    if (this.keepAliveInterval) {
      clearInterval(this.keepAliveInterval);
    }
  }
}
